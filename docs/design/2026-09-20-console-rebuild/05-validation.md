## 3. 独立读者审查与修订

按文档协作技能的独立读者检验流程，让另一位审阅者只依据方案及代码检查能否理解并实施。审阅发现并推动了以下修订：

| 发现 | 已完成修订 |
|---|---|
| 不同量表、权重和缺分口径不充分 | 补充版本化聚合公式、完整性分母、分歧定义和缺分算例 |
| 管理员接口与成员操作的边界含糊 | 补充现有权限矩阵；成员导航过滤；导出使用页内映射只读快照 |
| GRPO 下游容易退回 SFT | 增加 GRPO 数据集、样本、导出、问题清洗页面；未适配的评估明确不可启动 |
| 排队状态可能显示最终评估结论 | 未完成运行只显示进度和未就绪状态，完成后才出现报告 |
| 资源保存/停用与列表未同步 | 保存本地字段，同步状态及删除；密码不保存到浏览器 |
| 历史证据可能指向当前配置 | 增加标准历史版本与运行维度快照的独立只读页面 |
| 选择 #1026 却下载固定第一条示例 | 样本内容、导出预览与下载统一按 ID 读取，列表保留所选格式 |
| 复制内置维度覆盖原对象，且副本路由漏接 | 副本独立 ID=2，原内置项保持只读，副本可编辑且两条都保留 |

浏览器复验另发现表单控件 `name="dataset"` 遮蔽了 `form.dataset`，导致评估提交没有进入分支。原型统一改用 `getAttribute` 读取表单元数据，随后评估与清洗提交通过。只读维度被附加 `?mode=edit` 时也不再绑定不存在的输入控件。

这轮审查提高了方案可读性和原型一致性，不能代替真实目标用户研究。没有声称已经访谈用户、测出操作效率提升或通过完整 WCAG 审计。

## 4. 如何复现

```bash
node docs/design/2026-09-20-console-rebuild/prototype/build.mjs
python3 -m http.server 18422 --bind 127.0.0.1 --directory docs/design/2026-09-20-console-rebuild
# 浏览器打开 http://127.0.0.1:18422/prototype.html#/home
```

[browser-qa.js](prototype/browser-qa.js) 与 [sample-qa.js](prototype/sample-qa.js) 是供 Playwright CLI `run-code` 执行的函数，使用已经打开的 Chromium page。运行前创建 `output/playwright/console-rebuild/screens`；将 CLI 输出分别保存为该目录的 `qa-cli-output.txt` 和 `sample-qa-cli-output.txt`。然后执行：

```bash
node docs/design/2026-09-20-console-rebuild/prototype/package-evidence.mjs
```

打包脚本校验报告通过后才生成图册和验证 JSON。原型主文件不依赖上述工具，下载后可直接在浏览器打开。

## 5. 尚未完成的正式产品能力

本轮完成的是研究、设计、交互原型与远程可审阅材料。正式 React 前端尚未按方案替换。

原型只有少量代表数据，资源新增演示不等于完整多记录数据库；导出示例只演示有限样本和格式。部分生成、测试连接、通知操作演示确认与回执。跨刷新后台计时、服务端分页、任意筛选集合冻结、多人并发、可靠任务编排、真实模型请求和实际存储均未实现。

逐元素规格中的未保存拦截、列表返回位置恢复、全面键盘操作、资源引用校验、细粒度错误和版本冲突属于后续实施验收。正式实现的范围与依赖以 [实施计划](04-delivery-and-validation.md) 为准，不能仅凭原型可点击就标记完成。
