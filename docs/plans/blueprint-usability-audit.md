# 生产蓝图可用性审查

本审查对应 Atelier 项目的生产蓝图页面（`/p/:projectId/blueprint`），目标是找出“页面能看到但用户无法完成下一步”的信息孤岛，以及让首次使用者误解的术语。

## 发现

| 区域 | 信息孤岛/理解障碍 | 用户后果 | 处理方式 |
| --- | --- | --- | --- |
| 覆盖、标准、规则、交付 | 只显示版本选择，没有配置详情或下一步入口 | 用户不知道版本从哪里来、如何核对 | 节点显示当前引用版本、指纹，并提供对应配置入口 |
| 生成 | 没有连接或连接已停用时仍看起来可保存 | 到试制才失败 | 节点状态显示“缺少模型服务/模型服务已停用”，并指向连接设置 |
| 所有节点 | 只有“待交付”状态，没有完整度 | 用户不知道还缺多少配置 | 派生“可执行/待补齐/被依赖阻塞/待交付”状态，并列出缺失字段 |
| 枚举字段 | 把 `retry_then_skip`、`risk-based` 等内部值当文本输入 | 用户需要猜值，容易保存无效方案 | 用选择器展示中文含义，提交时仍保留稳定枚举值 |
| JSON 字段 | 普通文本框无即时状态、无示例，非法内容仍可能提交 | GRPO/步骤配置难以完成 | 增加格式化、示例、合法性状态；非法 JSON 禁止保存 |
| 术语 | schema、seed、hash、模型连接等工程词出现在主界面 | 用户不理解字段意义 | 主标签改为“输出内容类型/可复现抽样编号/内容指纹/模型服务”，技术值只作辅助信息 |
| 项目概览 | 旧能力迁移矩阵混入主流程 | 主线被迁移说明打断，形成第二套“兼容页面” | 从项目概览移除；迁移边界写入 Issue/PR，旧资产通过历史只读入口访问 |

## 配置闭环

蓝图引用的四类文档不再是只读列表。每个入口现在都能完成同一条闭环：

1. 打开当前版本，看到真实字段而不是版本号占位。
2. 在页面内编辑领域/方向、思维步骤、规则或交付字段映射。
3. 填写变更理由并保存为新版本；旧版本保持只读，批次快照不会被改写。
4. 从版本历史打开任意版本，或复制成当前草稿继续调整。

| 入口 | 可编辑内容 | 空态引导 | 回到蓝图的结果 |
| --- | --- | --- | --- |
| 覆盖矩阵 | 领域、稳定 ID、方向、配额、来源说明 | 添加领域/方向 | 版本列表可直接选择 |
| 思维标准 | 步骤 ID、名称、具体做法、完成检查点、顺序 | 添加步骤 | 生产前能看到每一步缺口 |
| 规则策略 | 匹配方式、字段、严重程度、建议动作、表达式、关键词 | 添加规则 | 预览可选择已保存版本 |
| 交付映射 | 格式、交付字段、来源字段、是否必填 | 添加字段 | 发布页选择版本，不再手填 ID |

这些编辑器共用 `useVersionedDocument`，因此乐观锁冲突、历史只读和保存反馈不会在不同页面产生不同语义。

## 蓝图节点执行前语义

- **可执行**：所有必填配置齐全，且生成节点引用了可用模型服务。
- **待补齐**：仍缺少一个或多个用户可填写的必填字段。
- **被依赖阻塞**：模型服务缺失或已停用，当前方案不能进入试制。
- **待交付**：服务端元数据标记为尚未接入，页面不提供“假配置”保存动作。

这些状态只反映当前草稿和连接目录，不代替服务端最终校验。保存仍通过版本化文档 API，并保留乐观锁与变更理由。
